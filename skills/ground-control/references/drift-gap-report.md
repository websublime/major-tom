# Drift/gap report template

One shape for every drift or gap, so any session or coordinator reports it the same way. Fill it in the conversation or the gate output; land the fix in the real docs; log the outcome in the status registry and the commit message. Version control is the archive: do not keep the filled report as a standalone file.

- **Class**: drift (two authorities disagree) or gap (an authority is silent where it must speak)
- **Sides**: <A: path or section> vs <B: path or section>
- **What each says**: <one tight line per side, quoted where it matters>
- **Authority per the hierarchy**: <which side should win and why; flag when the drift may be an SSOT bug instead>
- **Blast radius**: <every doc or component that restates the losing side>
- **Resolution**: <the fix as landed, with its commit or diff reference; or the owner question when it is a genuine fork>
- **Logged**: <the status registry entry or task updated>
